\chapter{Research Methodology}

\section{Research Design}

\subsection{System Development Life Cycle Model}
The study employs the Agile Software Development Life Cycle model. Agile was chosen for its flexibility and iterative nature, allowing continuous feedback from TTBDO personnel and early validation of system components. Through incremental sprints, the researchers were able to refine features based on actual user input.

\subsection{Research Framework}
The Problem Identification stage corresponds to the Introduction of the study, where the limitations of the current manual IP tracking process within the university are defined and contextualized. The Literature Review aligns with the Review of Related Literature (RRL) section, which explores local and international studies on IP management systems, theoretical foundations, and best practices to establish a strong research background.

Next, the Requirements Gathering phase reflects the Requirements Elicitation process. At this stage, system requirements are derived from user interviews, document analysis, and process observations. The insights gained are analyzed further in the Requirements Analysis and System Requirements Specification (SRS) stages, where functional and non-functional requirements are organized and translated into system features and design models.

Finally, the Testing and Evaluation phase aligns with the Methodology section, specifically the evaluation component. This phase involves validating the system’s functionality, usability, and performance through User Acceptance Testing (UAT) and other assessment methods to ensure that the developed IPMS meets the users’ needs effectively.

Overall, the framework ensures that each stage of the research process, from identifying the problem to evaluating the final system, is logically aligned with the structure of the study, ensuring coherence between the conceptual, analytical, and technical components.

\subsubsection{Hardware Specifications}
The following hardware specifications outline the minimum requirements used during development and testing. 

\begin{itemize}
  \item Processor: Intel Core i5 
  \item RAM: Minimum 8 GB 
  \item Storage: 512 GB SSD 
  \item Internet Connection: 30 Mbps minimum 
  \item Devices for testing: Desktop and Laptop Computers
\end{itemize}

Devices are equipped with an Intel Core i5 processor and at least 8 GB of RAM to ensure stable performance when running development tools and the system itself. A 512 GB SSD provides fast storage access, contributing to smoother operation during testing. An internet connection of at least 30 Mbps is required to support online services such as Supabase and GitHub. 
To verify system performance across various setups, testing is conducted on both desktop and laptop computers, ensuring the system operates reliably on different device types.

\subsection{Technology Stack}
Table~\ref{tab:tech_stack} outlines the technology stack used in developing the system. This stack ensures that the system remains efficient, secure, and user-friendly across all layers, from the interface to the backend and database.

The frontend of the system is built using HTML5, JavaScript, and Tailwind CSS. These technologies provide a responsive and accessible user interface, enabling technology generators and other organizational roles to perform various tasks such as submitting forms, reviewing IP documents, and tracking application statuses. On the other hand, the backend is developed using Express.js, which supports secure server-side processing and efficient handling of API endpoints that power the digital submission workflows, automated notifications, and dashboard analytics. 

The database is managed using Supabase, which offers structured and reliable data storage, real-time updates, and easy integration with JavaScript-based applications. Supabase ensures that IP records, notifications, and logs are stored efficiently and securely, allowing for prompt access to support decision-making, reporting, and compliance with IPOPHL deadlines. Furthermore, its built-in authentication and storage APIs streamline user management and secure document handling for various IP forms.

\subsubsection{TTBDO Admin}
The TTBDO Admins are the key stakeholders of the system, and as such have full access to the functionalities of the system. It includes managing the accounts of the users, the documents relating to every IPR application, the IPR status and critical deadlines, as well as having a full overview of the entire IP portfolio of the university. They can also gather reports of the IP portfolio from the system, which they can later use for further IP-driven strategies and decisions. 

\subsubsection{Tech Generators}

The Tech Generators, or the university researchers and IPR applicants, have the primary interaction of overseeing the current status of the IPs related to them. That is, if they are a member of the tech generators of a certain IP. They can also access and file disclosure forms to start their IPR application. The Tech Generators are notified by the system every time there is a status change to their IPR, may it is in the process of applying or while maintaining their rights to it. Aside from this, they also have viewing privileges to the IP portfolio summary and the published IPs of the university.

\subsubsection{UP Officials and Guests.}

These stakeholders in the system only have viewing capabilities with the IP portfolio summary as well as the published IPs of the university. The UP officials, however, have extended privileges to have an overview of the unpublished IPs or the ongoing IPR applications.

\section{Testing and Evaluation}

Testing ensured that all system features met the defined functional and non-functional requirements of the proposed system. The process covered multiple testing levels to validate performance, security, and user satisfaction.

\paragraph{Testing Approach:}

\begin{itemize}
  \item Performance Testing 

  \begin{itemize}
    \item Evaluated the system’s responsiveness, stability, and resilience under load. Page 
    load time was maintained below three seconds on average. Penetration testing was 
    conducted to assess the system’s defense mechanisms against unauthorized access 
    and vulnerabilities. 
  \end{itemize}

  \item User Acceptance Testing (UAT) 

  \begin{itemize}
    \item Involved end-users in evaluating the system’s overall usability, functionality, and 
    reliability. Feedback from evaluators rated the interface as “very satisfactory,” 
    with no system crashes observed during testing. 
  \end{itemize}
\end{itemize}

\paragraph{Evaluation Criteria:}

\begin{itemize}
  \item Functionality: All modules are operational and aligned with defined requirements. 
  \item Usability: Interface rated “very satisfactory” by evaluators. 
  \item Performance: Average page load time maintained under three seconds. 
  \item Reliability: No critical errors or crashes occurred during UAT. 
\end{itemize}
