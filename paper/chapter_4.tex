\chapter{Results and Discussion}
This chapter presents the IRIS web application, highlighting its key features and user interfaces. The system demonstrates functionalities such as authentication with role-based access control, application creation and management, notifications, dashboards, and access to IP application documents and guides. Screenshots illustrate the perspectives of Technology Generators, TTBDO admins, UP officials, and Guests, showing both view-only and full management capabilities, as well as the workflow of starting and tracking IP right applications.

\section{System}
\subsection{Authentication}
The IRIS system handles authentication for registered accounts. It has protected routing for role-based access control (RBAC). It facilitates sign-in with Google emails that should already be registered with Supabase.

Both the technology generators and the TTBDO admin can view a list of applications. They can also interact with a specific application, which prompts them to a different web page that shows specific details about that application.
This section will show the different views of a specific application for both the technology generator and the TTBDO admin, as well as the different features that are available for each user role on that specific application page.

\subsubsection{Technology Generator General Application View}
The web page shown in \figref{fig:techgen_appview} shows the perspective of a  
technology generator when they want to view more details about a specific IP right application.

Some steps on the trackbar of the application stage reflect the TTBDO's citizen charter where it shows whether the current step is within or over the processing time.

\subsubsection{Technology Generator Application Attachments View}
IRIS only allows creation, reading, and updating of the attachments of the IP right application; once an attachment is uploaded, it can never be removed in the system. 
Moreover, IRIS only allows specific file formats for the attachments, which are PDF, DOC/X, and XLSX. 
The application attachments view is shown in \figref{fig:techgen_attachments}, where the technology generator can see the list of attachments, upload new attachments, and update existing attachments. 
The technology generator can also see the history of all attachments that have been uploaded to the system for that specific application. 
As shown in \figref{fig:techgen_view_attachmentA}, the system integrated a versioning system for the attachments, to maintain a record of all changes made to each attachment. 
It is also seen in \figref{fig:techgen_view_attachmentC} that the system allows multiple file uploads at once, and what file types the system only allows.

\subsection{Start an Application}
The IRIS enables technology generators to start their IP right application through the system. 
For cases that all collaborators of the IP right application do not have IRIS accounts, the admin can start the application on behalf of the technology generator, and then link the technology generator to the application later on when they have an account in the system.
It is important that the system allows admins to create applications so that these can be tracked in the system, even if the technology generators would not use the system.

\subsection{Notification}
IRIS has a notification component that is only available for technology generators and the TTBDO admin. Whenever there are changes (e.g., attachments submitted, status updated, title updated, application stage moved etc.) on an application, the technology generator is notified. Moreover, the TTBDO can also see notification whenever there are new applications started, or they have been contacted by a technology generator. \figref{fig:notification} shows the panel that pops up whenever the authenticated users interact with the bell icon on the top bar. The panel shows the notifications that are chronologically ordered to show the latest notification at the top.

\subsection{Application Registry}
The Application Registry provides users with a quick overview of all IPs, allowing them to easily browse and reference relevant information. 
The registry is similar across user roles as seen in \figref{fig:registry}, but there are certain differences based on user roles. 
\figref{fig:registry_techgen} shows that the technology generators can only see the applications that they are involved in. They also have an action button to view the details of each application in their registry.
On the other hand, admins have total access, as illustrated in \figref{fig:registry_admin}, to all the IP portfolio of the system. Aside from viewing the details of each application, they can archive an application which hides the application from the registry but does not delete it from the system. 
It is important to note that archived applications are not counted in the system's metrics, ensuring that the data reflects only active applications. 

Guests and UP Officials have a similar view of the registry which is a read-only access, as shown in \figref{fig:registry_guest_official}. 
Guests can only see public applications while UP Officials can see all applications in the portfolio.

\subsubsection{Application Registry Filters and Sorting}
The application registry includes a filtering system that allows users to easily find specific applications based on various criteria as shown in \figref{fig:registry_filters}.
The filters include status, IP type, college names, names of technology generators, IP title, and project title.
The filters are available for all user roles, however, the guests cannot filter by status as this information is not available to them. 
On top of that, the application registry also supports sorting functionality to help users organize and prioritize their search results.
The sorting options include sorting by filing date, IP title, registration date, date added, and date.
